# 共有世界の本番公開

## 生成制限

背景と小物は部屋共通のimage_generation予算を使う。容量1、30秒に1枚。最初の変更から4秒で現在の共有枠を評価し、連打で期限を延長しない。背景優先で始め、未生成の背景と小物を交互に処理する。同一素材、キャッシュ、物理効果は新規生成権を使わない。

トークンと処理IDは外部処理より先に保存する。外部処理開始後の失敗・結果不明は返却も自動再送もしない。無人時に生成しない。リセットでは世代を更新するが、消費したトークンは維持する。画像の金額予算、通常会話・自発発話の制限は変更しない。

## 本番の分離

本番の既定部屋はmain-world。トップページから匿名guestで参加する。サーバーは設定された公開部屋だけを冪等に作成する。他の部屋は招待が必要。ステージングの既定部屋は変更しない。

本番保存Workerはvayria-shared-world-production。実行先はvayria-webのWorldExecutionだけ。stagingの保存Worker、R2、Cookieは流用しない。公開部屋は空の共有枠・履歴・生成物から始める。

## 初回と以降の手動公開

PRODUCTION_DEPLOY_ENABLEDはfalseのまま。mainのCIとステージング成功を確認する。初回だけ、本番用のstorage-bootstrapを先に実行する。これは実行先未登録でも保存Workerを作成できる。通常のdeployは本体の後に保存WorkerのRPCを有効化する。bootstrapを稼働中の本番へ再実行しない。

CI workflow_dispatchのpublish_production=trueは、そのmainの一回だけ本番公開する。通常のpushや入力未指定のdispatchは本番へ公開しない。手動CLIもmainのSHA・配信先・VRMハッシュ・ステージング成功を検証する。既存予算とシークレットは維持する。

障害時は直前の実行Workerと画面へ戻す。部屋DBと使用量台帳を削除しない。画像だけを止める場合も会話の制限を変更しない。

## 確認記録

本番既存上限（公開前の管理APIで確認）: 日額200円、月額API 3500円、画像系累積5ドル。値は拡張しない。自動検証、実APIの生成/キャッシュ、画像取得/表示、iPad実機の性能は別々に記録する。
