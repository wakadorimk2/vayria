# カード差し込みと会話の同時操作

カード交換は会話中も受け付ける。人の発話中と音声認識中は、カード単独の発声を始めない。

## 返答の切り替え

- 返答の生成中は、同じ質問を保持して最新のカードで生成をやり直す。
- 音声の再生中は、現在の発話単位を最後まで再生する。未再生の旧音声は破棄する。
- 続きは短い受け取りの言葉から始める。元の質問や話題を保ち、新しいカードの影響を出す。
- 人が話し始めた場合は、既存の音声割り込みを優先する。発言の確定までカードによる発声を保留する。
- 切り替え前に複数の交換を受け付けた場合は、最新のカード状態を使う。既存の交換回数制限は変更しない。

## 状態とAPI

- `swapRevision` は交換の所有者を識別するローカル番号。リセットでも進める。APIへ送信しない。
- 再生完了した返答だけが、その番号のカード指定を消費する。古い完了通知は新しい交換を変更できない。
- `/api/chat` の任意フィールド `cardContinuation` は、再生済みの `deliveredText` と受け取り済みかを示す `acknowledgementDelivered` を持つ。指定時は `forcedCardId` が必要。
- 継続は同じ会話履歴へ追記する。元の質問と未再生の返答を重複登録しない。
- 通常応答はクライアントで文へ分割する。ストリーミング応答はサーバーが発話単位を返す。引用符や単語の途中では分割しない。
- 1つの生成単位から最大8個の音声単位を作る。残りの文は最後の単位へまとめる。TTSの `unitIndex` は0〜15を受け付ける。
- 公開版は各音声単位に対応する署名済みチケットを発行する。通常応答は `ttsTickets` 配列、ストリーミング応答は各イベントの `ttsTicket` を使う。
- 公開版の会話・カード・音声認識・TTSは、受付時の `busy` (HTTP 429) に限り最大5回再試行する。再開時刻に従い、各待機は250ミリ秒〜5秒とする。同じ入力とTTSチケットを保持する。入力取消しやセッション交代で再試行も止める。利用枠超過や生成失敗は再試行しない。
- 音声認識は待機と応答本文の読取を含めて45秒で打ち切る。マイクの復帰後に次の発言を受け付ける。期限後に届く古い認識結果は使用しない。
- 生成失敗ではカード指定を保持する。セッションのリセットは保留中の継続を破棄する。

## 検証

`npm run test:performer` は会話中の交換、連続交換、遅延した完了通知、履歴、失敗、リセット、API検証を確認する。
`npm run test:public` は分割音声のチケットと継続リクエストの受付待ちを確認する。
音声入力、再生、ルーターの関連テスト、型検査、lint、通常版と公開版のビルドも実施する。

実機確認では、返答の前半でカードを差し込み、「短い区切り→受け取り→元の話の続き」を確認する。
人が話しながら差し込む場合も確認する。
実際の声、間、カードの影響の自然さは、モックによる自動テストでは確定しない。
