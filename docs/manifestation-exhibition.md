# 単一スロットと生成小物

**更新:** 動画の不採用判断を撤回した。段階別計測と中継配信を追加し、ローカル実験では動画を暫定採用した。詳細は [レイテンシ再検証](./manifestation-latency.md)。以下の旧比較結果は履歴として残す。

## 起動

`npm run dev:manifestation:op` で、既存の1Password参照を使って起動する。
通常起動では `VITE_MANIFESTATION_ENABLED=false`。公開Workerには追加しない。
展示モードでは `VITE_MANIFESTATION_ENABLED=true` を明示する。
旧 `VITE_WORLD_MUTATION_ENABLED` より新しいフラグを優先する。同時には動かさない。

サーバー設定:

| 変数 | 値 |
| --- | --- |
| `FAL_KEY` | falのサーバー用APIキー。1Password参照を利用できる |
| `RUNWARE_API_KEY` | **runware.ai** のキー。Runwayのキーではない |
| `VAYRIA_MANIFESTATION_PROVIDER` | `fal` / `runware` |
| `VAYRIA_MANIFESTATION_MODE` | `reused-base-video` / `fresh-image-then-video` / `fresh-image` |
| `VAYRIA_MANIFESTATION_RESOLUTION` | `480p` / `768p` |
| `VAYRIA_MANIFESTATION_BENCHMARK` | 比較画面から有料比較を実行する場合のみ `true` |
| `VAYRIA_MANIFESTATION_RUNWARE_ENABLED` | 正しいRunwareキーを設定した場合のみ `true` |

秘密値に `VITE_` を付けない。実装は秘密値をブラウザーに送らない。

## 境界

- `InputEvent` は入力の通知。人物、端末、セッションを別の識別子で扱う。
- `ManifestationSession` は同一セッションの投入順、生成待ち、表示済み対象を管理する。
- `GeneratedObject` は生成済みメディアと合成方法。`Manifestation` は表示履歴と配置対象。
- 内部5枠を維持する。同じカードは強化する。新しいカードは最も古い強化順の枠へ入れる。
- カード選択UIは4種類。内部の手札には限定しない。
- 会話は既存のカード交換・発話継続処理を使用する。画像プロンプトは会話へ渡さない。
- 現在見える対象と過去の出来事を会話文脈で区別する。配置不能な対象は存在を断定しない。
- 動画の内容を画像解析したとは扱わない。具体的な動きは断定しない。

## 表示と制限

通常の投入では5秒以内に読み込めた生成物を表示する。期限後は代替素材で確定する。
10秒で通信を中断する。プロバイダー側の課金停止を保証するものではない。
新しい投入では、表示済み対象をすぐ消さない。最大3個。15秒、30秒、45秒で段階退場する。
時間経過だけではAPIを呼ばない。最新の投入を大きく見せる。
顔・字幕・操作領域を避ける。カメラを引いて手を見せる処理はない。
同時生成2件、待機1件。待機超過は古い未開始要求を代替素材で完了する。

`POST /api/manifestation/experiments` は明示的な実験を作る。
`POST /api/manifestation/generate` は実験IDとInputEventを受け取る。
メディアは検査してローカル保存し、同一オリジンのURLを返す。
入力サイズ、重複イベント、オリジン、メディア形式、転送サイズを制限する。

台帳は `.world-experiments/manifestation/budget.json`。
合計予約額は10米ドル、各実験は20API要求まで。失敗・取消も予約を戻さない。
画像・動画・背景除去を別々に計数する。画面リセットで台帳を消さない。
旧世界改変の台帳は変更しない。

## 比較方法

開発情報の比較画面を使用する。API送信からブラウザーの切り抜き描画までを測る。
通常会話との音声同期は、比較キャンバスとは別に実際の投入で確認する。
比較モードの通信上限は150秒。通常表示の5秒基準を変えない。
結果JSONを保存する。中断した試行も残す。認証失敗はモデル性能とは区別する。
少数試行のp95は参考値。自動切り抜き検査だけで画質合格とはしない。
動画全体の輪郭・ちらつき、実機の配置、面白さは別に評価する。

## 検証

`npm run test:manifestation` に固定時計、キュー、世代、費用台帳、API契約、無効時のテストを置く。
既存 `npm test` にも追加した。`npm run typecheck`、`npm run lint`、`npm run build` を併用する。
実測結果と未確認項目は完了報告で分ける。

## 2026-09-10 実測と採用判断

通常設定は `fal / fresh-image`。FLUX.2 klein 4Bで768×768を生成し、BiRefNetで背景を除去する。
動画は5秒基準を満たさなかったため、通常経路に採用しない。

| 条件 | 試行 | 合成成功 | 5秒以内 | p50 / p95（秒） |
| --- | ---: | ---: | ---: | --- |
| fal・元画像動画480p | 5 | 5 | 2 | 5.36 / 8.60 |
| fal・元画像動画768p | 5 | 5 | 1 | 5.50 / 6.75 |
| fal・新規画像→動画480p | 5 | 3 | 0 | 7.10 / 7.87 |
| fal・新規画像→動画768p | 5 | 0 | 0 | 算出不可 |
| Runware・元画像動画480p | 5 | 5 | 0 | 15.20 / 24.67 |
| Runware・元画像動画768p | 5 | 5 | 0 | 14.91 / 16.40 |
| Runware・新規画像→動画480p | 1 | 1 | 0 | 28.61 / 28.61 |
| Runware・新規画像→動画768p | 1 | 1 | 0 | 26.76 / 26.76 |
| fal・実生成静止画＋背景除去 | 5 | 5 | 5 | 4.21 / 4.84 |

値はAPI開始から比較キャンバスの初回描画まで。p50/p95は成功試行だけ。nが小さいため参考値。
合成成功は自動検査。動画全編のちらつきや輪郭の目視合格を意味しない。
fal新規動画の失敗はクロマキー検査で除外した。矩形動画を代わりに表示しない。
Runware新規画像経路は予算を優先して各1回で終了した。誤ったRunwayキーの401は表から除外した。
再利用画像の両社比較は同一の鶏PNGと動作指示。新規画像経路は生成画像そのものが異なるため、純粋な動画事業者差とは扱わない。
数値の元記録は `manifestation-benchmark-2026-09-10.json`。ローカルのメディアURLを省略して保存した。

通常のカード操作では、最初の3回中1回が実生成を3.959秒で表示した。
残る2回は5.063秒と5.047秒で代替表示した。遅着画像の差し替えはなかった。
比較専用の5/5成功だけで、通常プレイの90%達成とは判定しない。
静止画は暫定採用。1.5〜3秒の目標は未達。

確認済みの生成PNG3種類を `public/manifestation` に同梱した。
輪郭と全身を目視確認した。細い緑の縁が一部残るため、展示サイズでの最終画質評価は別途必要。
代替素材は直前と同じものを避ける。通常成功時は先に代替素材を表示しない。

音声開始との時間差は未測定。ローカルAivisSpeechが `py-cpuinfo` のCPU判定エラーで起動できなかった。
音声時刻は最新入力後の再生開始を記録する。人物推定や発話内容の帰属を保証する計測ではない。
相棒感、面白さ、会場での操作、実際の複数参加者はOwner Playcheck未実施。

開発情報の「新しい実験」は20要求の実験枠だけを新設する。10米ドルの総台帳は維持する。
費用予約は静止画1投入0.15ドル、元画像動画480p/768pは0.125/0.20ドル。
新規画像動画はさらに0.10ドルを予約する。割引に依存しない保守的上限であり、請求実績ではない。
展示用予算は別途見積もりと承認が必要。現在の10ドル上限を自動解除しない。


追加の縦長確認では、画像準備は3.901秒で完了したが、配置候補不足で初回表示が遅れた。
下側左右の候補を追加した後は、代替素材を5.019秒で表示した。
顔・操作の重なりは確認したが、390×844では小物が小さい。見やすさは未合格。
横長では左右2体の共存を確認した。3体同時の実機確認と演出3種の目視確認は未完了。

最終の保守的予約総額は9.825米ドル。残り0.175米ドル。追加の有料比較は実行しない。
全 `npm test`、型検査、lint、ビルドは成功。ビルドには既存の500kB超チャンク警告が残る。
公開・push・mergeはしていない。
