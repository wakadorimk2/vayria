# 公開版の挨拶導線

2026-09-09。基点はmain `c0c26fb`。ローカル実装であり、公開配信は未実施。

## 体験

リンクからスマホで初めて訪れた人が、話題を考えずにVayriaの返答を受け取る入口を作った。
初回はカードを畳み、「挨拶してみる」と音声・字幕の案内を表示する。
返答を受け取ると、文字・マイク・カードから続ける案内へ切り替える。
挨拶は必須ではない。ガラスパネルから各操作を直接選べる。

- ガラスパネルはカード、文字、マイク、音声、設定の順に表示する。
- カードアイコンで脳内と手札を開閉する。閉じても交換結果と会話は保持する。
- カードと文字入力は排他表示とする。閉じた領域はinertとaria-hiddenで操作対象から外す。
- 接続確認と利用上限の案内は設定から分離する。キャンセル後は操作を選び直せる。
- 接続開始時に状態を取得し直す。最初の状態取得に失敗しても、操作を選び直して再取得できる。
- 初回案内の完了と開閉状態はページ内だけで保持する。期限切れでは挨拶を強制しない。
- マイク許可はマイク操作時だけ求める。公開版では、閲覧時の既存の相づちTTS先読みを停止した。

## 接続と生成

`/api/chat`に省略可能な `greeting: true` を追加した。manualモードだけで受け付ける。
通常会話では項目を送らない。不正な値、voice/autonomousとの併用は400で拒否する。
挨拶ボタンは履歴へ「こんにちは」を残す。生成指示を利用者の発言として保存しない。
サーバーはキャラクター設定に従った短い挨拶と、答えやすい質問一つを指示する。
挨拶時の二文目は質問を許可し、通常会話の文構成指示と分離する。
生成文の品質は実AIでの確認が必要である。

公開セッション確認と利用枠、TTSチケット、iOSの録音・再生切替は既存経路を使う。
一つの明示操作が接続確認を占有する。連打や別操作から確認待ちの処理を重複実行しない。
キャンセル・画面非表示・会話終了は、接続待ち操作の世代を無効にする。
遅れて届いた確認結果から、新しい会話やマイク取得を開始しない。
音声再生だけが止まった場合は既存の再開操作を使う。新しい自動生成リトライは追加していない。

## 確認済み

- 型検査、lint、展示モードbuild、公開版buildが成功した。500 kB超の既存チャンク警告は残る。
- 会話・演出247件、音声入力47件、再生40件、公開版37件、計371件のテストが成功した。
- 新規テストで、挨拶指示の分離、履歴の内容、通常会話への指定漏れ、用途の入力検証を確認した。
- 接続待ちの連打、キャンセル、画面非表示、終了、拒否、選び直しをテストした。
- ローカル模擬サーバーで、挨拶→接続→返答→継続案内、接続キャンセル、利用上限からの復帰を確認した。
- 新規閲覧とカード開閉後の模擬サーバー集計は、session GET=1、session POST=0、chat=0、TTS=0だった。
- カード交換後に閉じ、文字入力へ切り替え、カードを再表示して交換結果が残ることを確認した。
- カード開閉のSpace/Enter操作とaria-expandedの変化を確認した。
- 390×844でライト・ダーク、1280×720でデスクトップ表示を確認した。390×460では文字入力と送信ボタンが操作可能だった。
- 模擬返答は明示した固定テキストと無音WAVである。実AI・実音声の成功を意味しない。

## 未確認と次の評価

実AIの挨拶内容、実マイク、実TTSの聴感、iOS実機、実Turnstile、初見利用者の参加率は未確認。
390×460の確認は表示領域縮小の模擬であり、iOSのソフトキーボード動作の証拠ではない。

初見評価は新規ページから開始する。操作説明をせず、最初の返答に到達できるかと、次の操作を見つけられるかを観察する。
所要時間、迷った箇所、離脱、通信失敗を分けて記録する。未到達者を集計から除外しない。
現時点の画面評価は設計上の検討であり、視線計測や参加率改善の実証ではない。
公開前には対象ビルドを固定し、iPhoneで初回再生、連続会話、マイク停止、会話終了後の再開を確認する。
