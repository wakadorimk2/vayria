# 公開版の展示モード

展示でも一般公開と同じURL・ビルド・会話処理を使う。登録したブラウザーだけに展示枠を付ける。
この機能の実装はローカル変更。配信、本番展示枠の作成、有料生成はまだ実施していない。

## 当日の操作

1. スタンドに固定したiPadをインターネットへ接続する。PCとの端末間通信は必要ない。
2. 配信確認済みの公開URLを開く。設定の「展示の運営」で登録・期間・予算を確認する。
3. カード・文字・マイク操作から体験を始める。ページ表示だけでは録音・生成しない。
4. 来場者または運営者が「体験を終える」を押す。発話中も使える。
5. 「次の方もカードからどうぞ」を確認する。次の人が操作するまで待つ。

待機中は表情とモーションだけを動かす。カード操作への返答は行う。
終了時は前の会話、字幕、入力、カード配置・選択、録音・再生・処理待ちを捨てる。
音量・ミュートとテーマは既存の端末保存設定を引き継ぐ。マイクを自動再開しない。

終了通信に失敗した場合は再試行画面を表示する。再読込しても同じ終了要求を続ける。
前の会話へ戻さない。Cookieやブラウザーデータを消して復旧しようとせず、接続と登録状態を確認する。
登録はブラウザーのCookieに結び付く。別ブラウザー、プライベートブラウズ、Cookie削除後は再登録が必要。

## 管理者による準備

既存の `VAYRIA_ADMIN_SECRET` を安全な経路でPCのプロセス環境へ渡す。管理鍵をiPadへ入力しない。
接続先は `VAYRIA_ADMIN_URL` で明示する。本番操作は配信確認後に行う。

```powershell
$env:VAYRIA_ADMIN_URL = 'https://vayria.me'
npm run public:admin -- exhibition-create
npm run public:admin -- exhibition-code expo-20260923
npm run public:admin -- exhibition-list
```

標準展示枠は `expo-20260923`。2026-09-23 00:00から2026-09-24 00:00まで（日本時間）。
API推計予算は展示枠全体で10,000円。当日の設営確認も含む。既存IDでの再作成は拒否する。
コードは発行後15分で失効する。iPadの設定 → 展示の運営 → 端末登録コードへ入力する。
1コードは1回だけ利用できる。予備端末には同じ展示枠の別コードを発行する。
コードは一時的な資格情報。URLや公開資料へ記載しない。

リハーサルは別ID・期間・予算をすべて明示する。次は構文例であり、実行済みではない。

```powershell
npm run public:admin -- exhibition-create '{"event":"rehearsal-20260922","starts":"2026-09-22T12:00:00+09:00","expires":"2026-09-22T13:00:00+09:00","budgetYen":100}'
```

管理一覧は展示枠、使用額（micro-yen）、停止状態、端末ID、世代番号、失効状態を返す。
端末失効と展示停止は使用額を消さない。止めた展示枠を自動復帰・自動増額しない。

```powershell
npm run public:admin -- exhibition-revoke <一覧の端末ID>
npm run public:admin -- exhibition-stop expo-20260923
```

全体の緊急停止 `public:admin -- stop` とWorkerの `GENERATION_ENABLED=false` は展示にも適用する。
本番の配信・認証設定は既存の公開手順に従う。検証環境では検証用アクセスチケットも必要。

## 利用枠と費用

- 展示は一般向けの開始回数、180秒、会話・カード・音声の累積回数制限を使わない。
- 音声入力1回20秒、入力サイズ、同時処理数、要求タイムアウトは維持する。
- 一般公開の予算と使用額を変更しない。展示用の費用は展示枠へ集計する。
- 同じ展示枠の端末で予算を共有する。交代・再接続・コード再発行・再登録で使用額は戻らない。
- API呼び出し前に保守的な費用を予約する。確定額が得られれば精算する。不明な失敗では予約額を保持する。
- 予約を含む使用額が50%・80%に達すると設定ボタンに通知印を付ける。詳細は運営パネルで見る。
- 15秒ごと、および開始・終了操作時に状態を更新する。取得失敗時は古い値と明記する。
- 上限を超える予約は拒否する。残額があっても次の要求の予約額が収まらなければ開始しない。
- 推計値は税・為替・基盤費等を含む実請求額の上限保証ではない。5時間半の継続保証でもない。

## 実装と検証

`/api/admin` に展示作成・コード発行・端末失効・展示停止を追加した。
`/api/exhibition/enroll` はハッシュ化したコードをSQLiteのトランザクション内で一度だけ消費する。
`/api/exhibition/next` は要求IDと世代番号で重複・遅延を扱う。
`/api/session` は展示状態を返す。すべての生成はサーバー側で期間・権限・停止・予算を検査する。
既存台帳には省略可能な展示フィールドを追加する。一般用の使用額や設定を初期化しない。

```powershell
npm run test:public
npm run typecheck
npm run lint
npm test
npm run build
npm run public:build
```

任意のブラウザー確認は `scripts/public-exhibition-browser-check.mjs`。
Playwrightの場所を `PLAYWRIGHT_MODULE_PATH`、ブラウザーchannelを `PLAYWRIGHT_CHANNEL`（既定msedge）で指定できる。
先に公開ビルドを作る。APIはすべて模擬応答へ置き換える。画面記録は `.project-view/exhibition-check/`。

自動・模擬試験は実機の合格を意味しない。iPad実機の音声、長時間運転、会場回線、合計100W枠は未確認。
会場回線と充電を確保する。有線ハブを持っているだけでは、インターネット接続は保証されない。
