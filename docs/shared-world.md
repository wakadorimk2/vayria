# 永続共有世界

## 1枚の即時反応と生成予約

カードの扇状配置・浮き上がり・差し込み先プレビューは、元のカードUIと共用します。共有状態や抽選のルールは変わりません。通常画面から投入履歴と内部状態の一覧を除き、「次の参加者」を設定へ移しました。履歴は保存します。

受付時にモノの既存素材または簡略素材を少量表示し、環境の色と物理効果を反映します。重い処理は最後の成功した投入から4秒後にまとめます。拒否や重複再送では期限を変えません。部屋の生成予約は永続化しますが、参加者へのスナップショットには内部の予約情報を含めません。

カード定義から背景・小物・見た目の修飾を分けます。水中や宇宙は1枚で背景候補になります。場所は最後の投入を優先します。踊り・巨大化・無重力だけでは素材を再生成しません。会話モデルの生成提案も同じ待機列へ通し、カードに対応する素材キーへ統一します。通常会話が見送ってもカードの予約は残ります。

生成モードをONにした有効な参加者がいる場合だけ、既存の資格・予算内で画像を生成します。OFFの参加者しかいない場合は予約を保持します。ONへの切り替え後は在席更新で再評価します。会話を開始せずカードだけを挿した場合も即時演出は動きますが、画像生成には既存の接続・生成許可が必要です。自動で生成許可を広げません。

背景と小物は別の待機列です。1予約から必要な素材ごとに画像APIを呼び、同時数は部屋で最大2件です。実行中の追加投入は最新の状態へ集約します。完了後に静穏条件を満たした差分だけ処理します。請求結果不明・失敗の素材は自動再送しません。実行中のカード変更は有料処理をキャンセルしません。管理リセットは世代で旧処理を拒否します。移行・再接続だけで新規予約を作りません。

背景画像を隠していたテーマCSSの競合を修正しました。背景画像、環境装飾、透明なアバター描画、小物、字幕・操作部品の順に重ねます。新画像の読み込み成功までは旧画像を保持します。一画面の読み込み失敗で全員の素材を無効化しません。表示確認APIは status: load_failed を報告できます。成功した表示だけを会話へ戻します。

検証を分けて記録します。ローカルの模擬画像で背景の表示とアバターの前後関係を確認しました。390px幅で扇状手札・選択・タップ・ドラッグ・補充とフォーカス復帰を確認しました。外部APIの新規生成結果はステージング確認記録に記載します。iPad実機の30fpsと面白さは未確認です。

## 共有5枠と手札

従来のカード部品を使い、画面上部に全員共有の5枠、下部に各参加者の手札5枚を表示します。カードアイコンで開閉します。ドラッグ、手札と枠の順のタップ、Enter/Spaceで投入できます。種類が同じカードも、各1枚を別のIDで扱います。

保存Workerの `SHARED_HAND_ENABLED=true` で有効にします。`--shared-conversation` の配置手順はこのフラグも有効にします。無効な従来モードには既存の一覧UIを残します。

初回は50種類から同率で重複ありの5枚を引きます。投入成功時だけ1枚を消費し、その位置へ1枚補充します。使用した種類の抽選重みは直後の補充を含む3ドローで6倍です。同種の再使用は期間を更新し、倍率を加算しません。山札は枯渇しません。デッキの構成と抽選設定は生成処理から独立しています。

手札はWorldRoomのSQLiteに参加者別で保存します。本人にだけ配信します。再接続や会話終了では引き直しません。「次の参加者」はその参加者の手札を更新します。世界と共有枠は維持します。管理リセットは新しい世代で枠を空にし、手札と受領記録を更新します。

`POST /api/world-room/:room/insert` はイベントID、手札カードID、対象枠ID、対象枠の更新番号、部屋の世代を受け取ります。投入・消費・補充は一つの保存処理です。同じ枠への同時投入は先着だけ受け付けます。後着は最新状態と `accepted:false` を返し、手札を消費しません。同じイベントの再送では二重補充しません。従来の種類IDだけによる直接投入は、このモードでは拒否します。`hand-reset` は世代とイベントIDで重複を防ぎます。

現在の5枠は強いルール、履歴は弱い痕跡として会話へ渡します。重複枚数と枠順を維持します。無重力と水中、巨大と小さいは最後に投入した有効カードを優先します。通常投入では画像APIを即時に呼ばず、上記の4秒予約へまとめます。カードに由来する物理効果を生成物固有の効果へ焼き込まず、現在の枠から毎回求めます。生成中にカードが抜けても、古い結果はそのルールを復活させません。移行時には由来カードと一致する従来の効果を現在枠の効果へ分離し、素材・数量は保持します。

物理モード変更時、新しい物体は新しい設定で開始します。既存物体は位置と速度を維持し、1秒で設定を移行します。既存の背景、生成物、履歴には通常の減衰を適用します。

揃い演出は50種類すべてが対象です。同種5枠への遷移時に8秒間表示し、連打の30秒とは独立した60秒のクールダウンを使います。維持中の差し替え、クールダウン終了、再接続では再発火しません。モノは既存素材または簡略素材の群れ、他はカードの効果・色・モチーフを使います。背景画像に装飾を重ね、有料生成は呼びません。同時成立した連打と揃いは両方記録し、表示は揃いを優先します。合計96体の描画上限を維持します。

古い部屋は直近5件の投入を古い順に配置し、不足は空枠にします。移行だけで演出や画像生成を発火させません。部屋IDと既存リンクを維持します。

2026-09-13の手札追加分: 公開回帰200件と配置ガード25件が成功しました。50本のWebSocketで手札の本人限定配信と同時投入を確認しました。ローカルブラウザーでは、上下配置、タップ投入、ドラッグ投入、重複した手札、1枚補充を確認しました。iPad実機、実機30fps、揃い演出の面白さは未確認です。視線誘導の確認は設計上の評価であり、視線計測ではありません。

スマホと展示端末は同じヴェイリア画面を表示します。共有会話を有効にすると、WorldRoomが待機列と会話履歴を管理します。非公開のWorldExecution RPCが既存の生成処理を実行します。配信は展示端末の映像と音声をキャプチャします。

## 起動と運用

- Workerの `SHARED_WORLD_ENABLED=true` で有効化します。既定値はfalseです。
- ステージングのフロントエンドには共有UIを含めます。本番ビルドの共有UIは無効です。
- 既存の公開セッション、展示登録、生成予算を使います。参加リンクは公開会話の予算を付与しません。
- 管理端末で `npm run public:admin -- world-create ROOM_ID` を実行します。既存部屋に対しても参加リンクを再発行できます。
- 参加リンクと展示リンクは `.wrangler/world-ROOM_ID.json` に保存します。スマホ用QRは同じ場所の `-join.svg` です。展示リンクは主催者だけが使います。リンクをログや公開文書へ貼りません。
- 展示リンクを開き、既存の音声・公開セッションを開始します。画像生成は既存の「生成」操作で有効にします。
- `world-close ROOM_ID` は新しい投入を停止します。`world-open ROOM_ID` は再開します。世界の内容は保持します。
- `world-reset ROOM_ID` は1.5秒の掃除演出を通知し、新しい世代へ移します。過去の生成結果は受け付けません。
- 「次の参加者」は個人の会話セッションを交代します。共有世界を削除しません。
- 展示端末を交代する場合は、画面の「この端末へ展示を引き継ぐ」を使います。期限は30秒、更新間隔は10秒です。
- CIとPublic checksが成功したDraft PRを、`node scripts/staging-visual-preview.mjs SOURCE PR FULL_SHA --shared-world` でステージングへ配置します。既存の生成許可と予算を保持し、共有世界のフラグだけを有効にします。

## 入力・判断・描画

50種類のカードを5分類から選べます。投入上限は毎秒3枚、バースト10枚です。拒否された投入は成功表示しません。

通常のカード受付では画像を生成しません。既存の会話モデルが同じ応答に `worldIntent` を返します。由来カード、対象、世代、処理IDをサーバーが検証します。従来モードでは展示端末のリースも検証します。会話に渡す状態はサーバーが作成します。

一回の判断は最大4操作です。小物、背景、効果、複製を組み合わせます。小物の準備と表示を分けます。新しいカードは進行中の生成を取消しません。画像生成は既存の透過検査、キャッシュ、価格確認、予算制限を通ります。共有カードから動画は生成しません。

同じモノのカードが30秒に10枚届くと、群れを即時に準備します。以後30秒は群れへ集約します。この処理は外部生成を呼びません。対象の絵文字を簡略素材として使います。通常の会話モデルは群れの表示確認後に反応できます。

前景は3分、背景は30分です。その後は半減期24時間の痕跡になります。カードの短期重みの半減期は3分です。描画は通常24体、カオス時96体、背景6群に制限します。数量は描画数とは別に保持します。大量状態は一つの群れで保存します。

字幕と操作領域を通常は避けます。カオス時はアバターとカードを覆えます。演出はポインターイベントを取りません。操作位置の周辺は透過します。動きを減らす設定では静止表示にします。

## 保存と互換性

既存のPublicUsageとは別のSQLite-backed WorldRoomを追加します。保存先は外部HTTP経路を持たない `vayria-shared-world-staging` Workerです。展示Workerは `script_name` を指定したバインディングで接続します。ステージング画面を以前の版へ戻しても、保存Workerと世界を残せます。既存台帳のマイグレーションは変更しません。

保存Workerの削除やWorldRoomの削除マイグレーションは行いません。クラス削除は保存データも削除します。[CloudflareのDurable Object管理仕様](https://developers.cloudflare.com/durable-objects/reference/durable-objects-migrations/)を参照してください。通常の世界初期化には世代付きの `world-reset` を使います。

詳細投入履歴は10,000件です。古い項目は日別・カード別に集約します。重複防止の受領記録は別テーブルに残します。世界の描画要素は128グループまでです。上限を超えた古い概念も投入集計には残ります。

再接続は最新スナップショットを取得します。時刻付き演出を最初から再生しません。画像生成の要求済み状態を永続化し、再接続で有料生成を再送しません。開始済みの生成が90秒を越えると失敗として扱います。自動再生成はしません。

部屋用画像は専用R2キーへコピーします。元の公開セッションが終了しても、部屋の認証で取得できます。共有会話モードではスマホにも素材URLを渡します。

## 共有会話と物理描画

メインWorkerと保存Workerの `SHARED_CONVERSATION_ENABLED` を有効にします。フロントエンドの `VITE_SHARED_PHYSICS_ENABLED` はステージングのみ有効です。配置には `--shared-conversation` を使います。スクリプトは非公開RPCの入口、保存Worker、公開側の機能フラグの順に配置します。部屋IDと保存スキーマは維持します。

会話は部屋で一件です。全員同じ優先度のFIFOです。一人一件、部屋全体10件まで待機できます。受付後のクールダウンは3秒、待機期限は120秒です。音声はVAD開始時に予約します。録音は端末で保持し、順番が来てから送信します。取消・拒否ではSTTを呼びません。返答音声は一度だけ生成し、認証付きの部屋素材として配信します。音声素材は10分で取得不可になります。物理削除は取得時の遅延削除です。

展示端末が不在でも、利用資格を持つ参加者が会話できます。自発行動には接続中かつ画面が可視の有効セッションが必要です。未反映のカードを最低10秒待って判断します。会話と待機列がある間は自発行動を開始しません。iOSでは既存のエコー抑制のため、共有音声の再生中は録音を保留します。マイクONの設定は維持します。

カード一覧は既存のガラスパネルのカードアイコンから開きます。スマホでは下部シート、横長画面では右側のパネルです。常設の右下パネルは表示しません。

背景と小物は独立した生成待機列です。部屋内の合計同時生成は2件までです。既存の台帳と予算制限も適用します。物理変更と複製は生成APIを呼びません。背景は画像の読込み完了まで現在の画像を維持します。古い背景要求は新しい背景を上書きできません。

Matter.jsは固定時間刻みとスリープを使います。床、壁、物体同士の衝突を端末内で計算します。水中は浮力と抵抗、無重力は浮遊力、踊りは跳ねと横移動で表現します。背景の群れは物理計算から外します。位置は同期しません。素材ごとの矩形クリッピングを外しています。

## 検証

### 音声と表示の更新

共有音声の再生所有者はタブ内で一つです。部屋・世代・返答IDを再マウント後も記憶します。共有会話中のローカル発話は再生しません。開発ログの `[shared-speech]` は受信と実際の再生開始を区別します。本文の一致では重複を判定しません。

モノの投入は3体を追加します。通常24体、カオス96体の上限は維持します。生成後は既存の物体へ画像を適用し、追加の1体を作りません。基本サイズは短辺の18%（72〜168px）です。顔の横、狭い画面では顔の下から落下し、下半身の前にも積もります。字幕と操作は物理障害物にせず、前面表示で保護します。

初回案内の×と操作成功は `vayria-tutorial-dismissed-v1` をブラウザに保存します。「次の参加者」でも案内を復活させません。設定の「使い方」で開き直せます。ブラウザが保存を拒否する場合は、そのページ内だけ閉じます。

`npm run test:shared-world` は疑似モデル、SQLite-backed Durable Objects、50本のWebSocket接続を使います。外部生成APIは使いません。`npm run test:public` にも含まれます。
