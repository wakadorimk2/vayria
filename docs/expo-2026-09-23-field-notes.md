## 展示環境（観察された事実）

- 展示時間は 12:00〜17:30。
- iPadを展示端末として使用した。来場者自身のスマホからもQR経由で参加できる設計だった。
- 会場Wi-Fiが不安定になり、途中でサービス利用が困難な時間帯があった。
- 音声対話とカード操作の両方を含む展示だった。

## 来場者の行動

### 観察された事実

- 「展示物を勝手に触ってよいのか」が来場者には想像以上に分かりづらそうだった。
- 生成AIイベントに自発的に来る層であっても、QRコードを見て即座に自分のスマホを取り出し、読み取って参加する人はほとんどいなかった。
- カードを所定方向へしっかりスワイプさせる操作は、初見ユーザーにはやや難しそうだった。
- 操作を理解した一部の来場者は何度もカードを投入し、かなり長く遊んでいた。
- 来場者はVayriaをほぼ完全に「ゲーム」として認識していた。
- 遊んでいるうちに「どのカードを入れれば面白い／映える反応が出るか」を探すこと自体が遊びになっていた。
- 自然発生したループはおおむね次の形だった:
  `カードを見る → 面白い反応を予想する → 入れる → Vayriaの反応を見る → 次のカードを試す`
- カード投入後の反応速度について好意的な反応があった。
- 「面白い表現を探している」というドワンゴ関係者にも、カードの演出が意外なものとして受け取られた。
- デジタル画面そのものより、冊子などの物理媒体のほうが圧倒的に手に取りやすそうだった。

### そこからの解釈

- QRは実装上は簡単な導線でも、心理的には「スマホを出す」「読み取る」「未知のページを開く」「操作を理解する」という連続した摩擦が大きい可能性がある。
- 展示会場では音声対話は扱いづらい。騒音の影響に加え、カード体験と同時に提示すると導線が複雑になる。
- 「AIと会話するサービス」としてより「Vayriaから面白い反応を引き出すゲーム」として展示が成立していた可能性がある。
- 興味を持っている来場者は、視線、歩く速度、画面を繰り返し見る動作から意外と判別できた。無差別な声かけより、その判別に基づく声かけのほうがやりやすかった。

## 次回に試したい仮説

以下は仮説であり、決定事項ではない。

### 展示導線の仮説

- 冊子などの物理媒体を手前の入口にし、「この展示は遊べます」と明示してから実機へ誘導する。
- QRは体験開始の必須導線ではなく、体験後にWeb版・SNS・詳細情報へアクセスする二次導線にする。
- 理想的な入口は「説明を理解して操作する」より「手ぶらで触る → 即座に何か起こる」に寄せる。
- エレベータートークは必須。数秒で「何をすると何が起きる展示なのか」を伝えられる必要がある。

### UI / ゲームデザインの仮説

- 精密なスワイプ操作を要求しない。
- Slay the Spireのような気持ちよいカード操作を参考にしつつ、例えば軽く「シュッ」とするだけで手札全体がランダムに入れ替わる程度でもよい。
- `触る → 何か起きる → もう一度触る` までのTime to Funを極端に短くする。
- AIへの入力そのものを遊びに変換する。「AIの振る舞いそのものをゲームシステムにする」方向が重要そう。

### 計測の仮説

次回は最低限、匿名で以下のイベントを計測できるよう検討する。

- `session_start`
- `first_card_shown`
- `card_played`
- `second_card_played`
- `five_cards_played`
- 展示用QRには `?src=expo...` 等を付け、展示機自身のアクセスと来場者アクセスを分離する。
